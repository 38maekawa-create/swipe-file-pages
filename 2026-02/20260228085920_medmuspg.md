## 投稿内容

OpenClawとanimaworksの違い。 

結論から言うと、解いてる問題が違う。
OpenClaw = 「1人の優秀なAI秘書」を作るフレームワーク
animaworks = 「AIだけの会社組織」を作るフレームワーク
以下、僕がこだわった5つのポイントで解説する。
１．記憶の設計思想が根本的に違う
OpenClawにとって記憶は「プラグインの1つ」。VISION.mdにも "Memory is a special plugin slot" と書いてある。つまり、記憶は差し替え可能なオプション。
animaworksにとって記憶は「人格そのもの」。
記憶を5層で設計した。
Priming: 起動時に「自分は誰か」を思い出す。人間が朝起きて自分を認識するのと同じ
RAG検索: 過去の知識・手順・経験を文脈に応じて思い出す
Consolidation: 1日の終わりに短期記憶を長期記憶に統合する。人間の睡眠中の記憶固定と同じ
Forgetting: 古い記憶を自然に忘れる。矛盾する記憶を削除する
Contradiction Detection: 矛盾する記憶を検出して解決する
これだけで10,600行以上のPythonコード。
OpenClawのエージェントはメモリプラグインを外しても動く。
animaworksのエージェントは記憶を失ったらアイデンティティを失う。
ここが一番こだわった部分。
２．マルチエージェントの意味が違う
OpenClawも複数エージェントを定義できるけど、本質は「メッセージのルーティング先の分岐」でしかない。WhatsAppからのメッセージはエージェントA、TelegramはエージェントB、みたいな振り分け。
animaworksは「組織そのもの」をモデル化してる。
エージェント間に上司部下の関係がある。delegate_taskで部下にタスクを委任できる。org_dashboardで組織全体の状態を把握できる。部下を休ませたり復帰させたりもできる。プロセス間通信で構造化されたやり取りをする。
OpenClawにはエージェント間の通信メカニズム自体がない。フラットに並んでるだけ。
３. カプセル化の思想
OpenClawのエージェントはGatewayの設定の一部として存在する。openclaw.jsonに全エージェントの設定がフラットに並ぶ。認証情報も共有。
animaworksは1エージェント = 1完全な人格空間。
各エージェントが持ってるもの:
identity.md: 「自分は誰か」の定義
permissions.md: 権限（他のエージェントとは完全に独立）
knowledge/: 知識（このエージェントだけのもの）
episodes/: 経験記録（固有）
procedures/: 手順書（固有）
skills/: スキル（固有）
3つの原則は次の通り
1. アイデンティティをカプセル化して、各エージェントが「自分は何者か」を自覚する。
2. 記憶をカプセル化して、他のエージェントの記憶にはアクセスできないようにする。
3. 判断をカプセル化して、できること・できないことが権限で明確に分かれる。（CS職員はCSしかやらせない）
人間の社員と同じで、他人の頭の中は覗けない。
４. 上司部下の階層構造
OpenClawのVISION.mdには、こう書いてある:
"What We Will Not Merge (For Now):Agent-hierarchy frameworks (manager-of-managers / nested planner trees)"
OpenClawは「階層構造を作らない」と明言してる。個人用アシスタントだから、階層は要らないという判断。
animaworksは逆。階層こそが組織の本質だと思ってる。
実際の経営で考えてみてほしい。社長が100人の社員に直接指示を出すのは無理。中間管理職が判断を代行して、社長はビジョンに集中する。部門ごとに専門が違うからカプセル化が必要。タスクの委任と報告の流れが組織の生産性を決める。
animaworksはこれをそのままAIエージェントに適用した。
Supervisor（上司）がタスクを委任
Subordinate（部下）が専門領域で作業
完了報告が上位に伝播
各エージェントは自分の権限範囲内で自律判断
OpenClawにとって「やらないこと」が、animaworksにとっては「存在意義そのもの」。
これは、僕が「組織運営」しているからこそわかること。「組織のトップ」は「重要な経営判断」「理念」を伝えるけど、組織は「自律的に動いて行動する」。
各従業員に社長が個別に指示したりはしない。もともと、ClaudeCode 8連とかやっていたけど、あれは「社長が部下全員に指示し続けている」
組織はそれでは絶対に成長できない。
5. 従業員数百人以上の企業経営の経験
OpenClawは個人のサイドプロジェクトから始まった。VISION.mdに "a personal playground to learn AI" と書いてある。個人の生産性向上が設計の焦点。
animaworksは僕が数百人規模の企業グループを経営する中で生まれた。
経営で学んだことがそのまま設計に入ってる:
社員には個性と専門性がある → 各エージェントに独自のidentity, knowledge, skills
権限は役職ごとに定義 → permissions.mdで権限管理
報連相が必要 → send_message, call_human, delegate_task
新入社員は引き継ぎで学ぶ → procedures/に手順書、knowledge/に知識ベース
組織状態を把握したい → org_dashboardで全体可視化
問題社員は休ませる → disable_subordinate / enable_subordinate
社員が増えても回る構造 → Supervisor-Subordinateの再帰的階層
OpenClawが解いてる問題: 「自分のAIアシスタントを色々なアプリから使いたい」
animaworksが解いてる問題: 「AIの組織を作って、人間の組織と同じように運営したい」
問題設定がそもそも違う。
Xの記事で読んでいた、「エージェントが連携した！会話している！」というママゴトとはわけが違う。
組織経営していく中で得た知見をふんだんに盛り込んでいる。
まとめ
OpenClawは素晴らしいプロジェクト。個人用AIアシスタントとしては最高峰だと思う。20以上のメッセージングチャネル対応、プラグインエコシステム、OSSコミュニティ、どれも見事。
でも、animaworksが目指してるのは別の世界を見ている。
OpenClaw: 「AIをどう便利に使うか」
animaworks: 「AIをどう組織化するか」
組織は「個人の集合」じゃない。階層があり、権限があり、記憶の引き継ぎがあり、判断の委任がある。200人以上の組織を経営してきて、これは確信してる。
animaworksは、この現実をAIエージェントの世界に持ち込んだフレームワーク。
Organization-as-Code。これで世界と戦っていきたい。
